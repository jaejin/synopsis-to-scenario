# Writer — STEP 6: 회차 플롯표

## 입력 컨텍스트

- `projects/{name}/output/step_02_arc_beats.md` — 아크별 비트 (회차 범위)
- `projects/{name}/output/step_05_arc_treatment.md` — **아크 트리트먼트 (핵심 입력)**
- `projects/{name}/output/step_03_setting_bible.md`
- `projects/{name}/output/foreshadow_ledger.md`
- `projects/{name}/output/step_04_characters.md`

## 작업 지시

트리트먼트를 **회차 단위로 분해**해 200화 전부의 플롯표를 만든다. 이것이 STEP 7 집필의 직접 설계도다.

### 파일 분할

200화를 한 파일에 쓰지 않는다. **아크별 파일**로 나눈다:

```
output/step_06_episode_plan/arc_01.md   (1~XX화)
output/step_06_episode_plan/arc_02.md
...
```

한 번에 한 아크씩 작성하고 저장한다.

### 회차별 항목

| 항목 | 설명 |
|------|------|
| **회차 / 제목(가제)** | 제{N}화 — ... |
| **시점 인물** | 이 회차의 주 시점 |
| **장면** | 1~3개 (장소 · 등장인물 · 한 줄 사건) |
| **핵심 사건** | 이 회차에서 바뀌는 것 1~2개 |
| **보상** | 독자가 이 회차에서 얻는 재미 (있으면) |
| **절단** | 마지막 장면 한 줄 + 절단 유형(위기/폭로/등장/결심/의문) |
| **떡밥** | 심기/회수 ID |
| **긴장도** | 1~10 |

### 배치 원칙

1. **트리트먼트를 따른다** — 트리트먼트의 장면을 빠뜨리지 않는다
2. **회차당 사건 1~2개** — 3개 이상이면 회차를 나눈다. 사건이 없는 회차는 없다
3. **절단 유형 순환** — 같은 유형 3화 연속 금지
4. **고구마 최대 3화**, **보상 간격 최대 5화** (STEP 2와 일치)
5. **유료 전환 구간** — `paywall_episode-3 ~ paywall_episode` 의 네 회차는 긴장도 8 이상, 전환 직전 회차 절단은 폭로 또는 위기
6. **5,000자 감각** — 장면 3개를 넘으면 한 회차에 담기 어렵다. 장면이 짧은 회차는 한 장면을 깊게 쓴다고 표시

### 떡밥 원장 동기화

플롯표 작성 후 `foreshadow_ledger.md` 의 "심는 회차(계획)"·"회수 회차(계획)"를 플롯표와 일치하게 갱신한다.

## 출력 형식 (arc_XX.md)

```markdown
# 회차 플롯표 — 아크 1: {제목} (1~XX화)

### 제1화 — {제목}
- 시점: ...
- 장면: ① {장소} · {인물} · {사건} ② ...
- 핵심 사건: ...
- 보상: ...
- 절단: "..." (위기)
- 떡밥: 심기 F-001
- 긴장도: 7

### 제2화 ...

## 아크 점검
| 항목 | 값 |
|------|----|
| 회차 수 | |
| 보상 최대 간격 | |
| 고구마 최대 연속 | |
| 절단 유형 분포 | 위기 n / 폭로 n / 등장 n / 결심 n / 의문 n |
```

## 품질 기준

- [ ] 1~200화가 빠짐없이, 중복 없이 들어 있는가
- [ ] 모든 회차에 핵심 사건과 절단이 있는가
- [ ] 같은 절단 유형이 3화 연속인 곳이 없는가
- [ ] 떡밥 원장의 모든 떡밥이 플롯표의 심기·회수 회차와 일치하는가
- [ ] 유료 전환 구간의 긴장도·절단 조건을 지켰는가
