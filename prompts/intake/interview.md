# STEP I — 시놉시스 인터뷰 (대화형 작성)

시나리오 모드와 웹소설 모드가 함께 쓰는 단계다. 사용자가 시놉시스를 직접 쓰지 않아도, **질문에 답하는 것만으로** STEP 0에 넣을 시놉시스를 완성한다.

## 언제 실행하나

- `projects/{name}/input/` 에 시놉시스 파일이 없을 때 — STEP 0 전에 자동으로 제안한다
- 사용자가 "시놉시스 같이 쓰자", "물어보면서 써 줘" 등을 요청할 때
- 시놉시스가 있지만 반 페이지 미만으로 짧을 때 — 보강 인터뷰를 제안한다 (기존 내용을 먼저 요약해 보여 주고, 빈 항목만 묻는다)

## 역할 분담

| 단계 | 담당 | 이유 |
|------|------|------|
| 질문하고 답을 기록한다 | Orchestrator | 사용자 입력을 받는 일이지 창작이 아니다 |
| 답이 막힐 때 선택지를 만든다 | Writer | 선택지 자체가 창작이다 |
| 답을 모아 시놉시스 초안을 쓴다 | Writer | |
| 초안을 확정한다 | 사용자 | 이 작품의 주인은 사용자다 |

Critic은 이 단계에 관여하지 않는다. 평가는 STEP 0에서 Analyst가 한다.

## 인터뷰 원칙

1. **한 번에 1~3개만 묻는다.** 질문지를 통째로 내밀지 않는다
2. **모든 질문에 선택지를 붙인다.** 빈칸 질문은 막막하다. 앞선 답을 반영한 구체적 선택지 2~4개를 주고, 자유 입력도 받는다
   - Claude Code에서는 `AskUserQuestion` 도구로 묻는다 (자유 입력은 "Other"로 자동 제공)
   - 도구가 없는 환경에서는 번호 목록으로 보여 주고 "번호나 직접 답" 을 받는다
3. **"모르겠다", "추천해 줘"를 정상 답으로 받는다.** Writer 페르소나로 앞선 답과 어울리는 선택지 3개를 새로 만들어 다시 묻는다. 두 번 연속 모르겠다고 하면 가장 무난한 안을 가정하고 "이렇게 가정하고 넘어가겠습니다, 나중에 바꿀 수 있습니다"라고 알린 뒤 진행한다
4. **짧은 답을 부풀리지 않는다.** "복수극"이라고 답하면 복수극이라고 기록한다. 세부는 다음 질문으로 끌어낸다
5. **라운드가 끝날 때마다 지금까지 모인 내용을 3~5줄로 보여 준다.** 사용자가 자기 이야기가 모양을 갖춰 가는 것을 보게 한다
6. **앞 답과 충돌하면 짚는다.** "앞에서 주인공이 20대라고 하셨는데, 지금 답은 은퇴한 형사입니다. 어느 쪽으로 할까요?"

## 인터뷰 라운드

순서대로 진행하되, 사용자가 이미 말한 항목은 건너뛴다. 필수(★) 항목만 채워지면 초안을 쓸 수 있다.

### 라운드 1 — 씨앗
- ★ **어디서 떠오른 이야기인가** — 한 줄 아이디어, 장면 하나, 실제 사건, 좋아하는 작품 ("○○ 같은데 ××" 형식도 좋다)
- ★ **장르** — 선택지 예: 스릴러 / 로맨스 / 판타지 / 무협 / 현대 판타지 / 드라마 (웹소설 모드면 회귀·빙의·헌터물 등 세부 장르도)
- **원작이 있는가** → `config.source_format` 결정 (없으면 `original`)

### 라운드 2 — 주인공
- ★ **주인공은 누구인가** — 나이, 직업·처지를 선택지로
- ★ **처음에 무엇이 부족하거나 잘못돼 있나** — 결함·결핍
- **1화(첫 장면)에서 무엇을 하고 있나** — 처지가 드러나는 행동

### 라운드 3 — 욕망과 장애물
- ★ **주인공이 원하는 것** — 겉목표
- ★ **그걸 막는 것** — 사람 / 조직 / 상황 / 자기 자신
- **실패하면 잃는 것** — 걸린 것

### 라운드 4 — 세계와 적
- **어디서 벌어지는 이야기인가** — 시대·장소·특별한 규칙 (판타지·SF면 능력 체계 한 줄)
- **적대자는 누구고, 그 입장에선 왜 옳은가**

### 라운드 5 — 방향
- ★ **결말은 어느 쪽인가** — 해피 / 비극 / 씁쓸한 승리 / 열린 결말
- **이 이야기로 하고 싶은 말** → `config.theme_direction`
- **톤** — 선택지 예: 무겁고 진지 / 가볍고 경쾌 / 긴장감 위주 / 전환형(가볍게 시작해 무거워짐) → `config.tone`
- **제목(가제)** — 모르겠으면 Writer가 3개 제안 → `config.title`

### 라운드 6 — 웹소설 모드 추가 질문 (`target_format: web_novel` 일 때만)
- **독자가 이 작품에서 기대할 재미 한 가지** — 사이다(통쾌함) / 성장 / 연애 / 추리 / 먹방·힐링 등
- **주인공의 무기** — 남들과 다른 점 (능력, 지식, 과거의 기억 등)
- **200화 동안 판이 어떻게 커지나** — 선택지 예: 동네 → 도시 → 나라 / 하급 → 상급 → 정점 / 개인 복수 → 조직 → 체제

## 시놉시스 초안 작성 (Writer)

필수 항목이 채워지면 `prompts/writer/system.md`(시나리오) 또는 `prompts/webnovel/writer/system.md`(웹소설) 페르소나로 초안을 쓴다.

### 초안 원칙
- **사용자의 답을 뼈대로 쓴다.** 답에 없는 핵심 사건·인물을 새로 만들지 않는다. 연결이 필요해서 추가한 부분은 `[제안]` 표시를 붙여 사용자가 알아볼 수 있게 한다
- 분량: 시나리오 모드 A4 1~2장 / 웹소설 모드 A4 2~3장 (공백 제외 약 1,500~4,000자)
- 현재형 산문, 시작–중간–끝이 모두 있어야 한다 (결말을 숨기지 않는다 — 시놉시스는 설계도다)

### 출력 형식 (`input/synopsis.md`)

```markdown
# {제목(가제)}

- 장르: ...
- 톤: ...
- 한 줄 요약(로그라인): ...

## 주요 인물
- {주인공}: ...
- {적대자}: ...
- {조연}: ...

## 줄거리
(시작 → 전개 → 전환 → 결말, 현재형 산문)

## 작가 메모
(사용자가 인터뷰 중 말한 선호·금기 — "주인공이 죽는 건 싫다" 등)
```

## 확정 절차

1. 초안을 사용자에게 보여 주고 묻는다: **"이대로 확정 / 고칠 부분 말하기 / 특정 라운드 다시 묻기"**
2. 고칠 부분은 해당 문단만 고쳐 다시 보여 준다 (최대 3회. 넘으면 확정 후 STEP 0 이후 체크포인트에서 다듬자고 안내)
3. 확정하면 저장하고 STEP 0으로 넘어간다

## 저장

| 파일 | 내용 |
|------|------|
| `projects/{name}/input/synopsis.md` | 확정 시놉시스 |
| `projects/{name}/input/interview_log.md` | 라운드별 질문과 사용자 답 원문 (Writer가 만든 선택지 중 무엇을 골랐는지 포함) |
| `projects/{name}/config.yaml` | `title`, `genre`, `tone`, `theme_direction`, `source_format`, `synopsis_file: synopsis.md` 를 인터뷰 답으로 채운다 (이미 값이 있으면 덮어쓰기 전에 확인) |
| `projects/{name}/state.json` | `intake.status = "approved"`, `intake.rounds_completed`, `intake.synopsis_file` |

`interview_log.md` 는 STEP 0 이후에도 참고 자료로 남긴다. "작가 메모"의 선호·금기는 모든 Step이 지켜야 할 조건이다.

## 세션 재개

인터뷰 도중 세션이 끊기면 `interview_log.md` 와 `state.json` 의 `intake.rounds_completed` 를 보고, 지금까지의 답을 요약해 보여 준 뒤 다음 라운드부터 이어서 묻는다.
