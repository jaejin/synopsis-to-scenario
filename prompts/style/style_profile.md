# Writer — 문체 프로필 (고전 문체 차용, 두 모드 공통)

`config.yaml` 의 `style_reference.sources` 가 비어 있지 않으면, **첫 집필(STEP 7) 전에 1회** 실행한다.
원전의 문체를 **특징 단위로 분해해 규칙으로 옮기는** 단계다. 원전의 문장을 가져오는 단계가 아니다.

## 입력 컨텍스트

- `projects/{name}/config.yaml` — `style_reference` (원전·적용 범위·강도·가져올 것·뺄 것)
- `projects/{name}/input/references/style/` — 원문 발췌 파일 (`excerpt_files`, 있으면)
- `projects/{name}/output/step_04_characters.md` — 인물 말투 (대사에 적용할 때 충돌 확인)
- 웹소설: `projects/{name}/output/episodes/ep_001.md` ~ (이미 쓴 회차가 있으면 앞 3화까지) — 변환 예시 재료
- 시나리오: `prompts/writer/step_07_examples.md` — 형식 기준

## 원칙

1. **원문 문장·고유한 표현을 원고에 옮기지 않는다.** 가져오는 것은 리듬·어미·서술자의 거리·어휘층·비유 방식 같은 **특징**이다. 원전의 유명한 문장을 변형해 쓰는 것도 금지한다 (독자는 패러디로 읽는다)
2. **저작권 상태를 먼저 적는다.** 한국 기준 저자 사후 70년이 지난 공유저작물이면 프로필에 짧은 인용(1회 2문장 이내, 전체 5회 이내)을 둘 수 있다. 보호 중인 작품이면 인용 없이 특징만 적는다
3. **원문 대조 여부를 밝힌다.** `excerpt_files` 가 없으면 기억에 의존한 분석이므로 프로필 첫머리에 `원문 대조 없음`을 적고, 사용자에게 발췌 파일을 넣도록 권한다 (기억 속 원문은 틀릴 수 있다)
4. **형식 규칙이 문체보다 먼저다.** 분량, 웹소설 모바일 문단(1~3문장), 대사 1개 = 문단 1개, 시나리오 형식(S#·지문 3~4줄·카메라에 보이는 것만)은 문체 때문에 깨지 않는다. 충돌하면 아래 "충돌 조정"에서 문체 쪽을 바꾼다
5. **특징은 측정할 수 있게 쓴다.** "해학적이다"가 아니라 "장면마다 서술자가 인물을 비꼬는 논평 1회, '~것이다'로 끝냄"처럼 쓴다. Critic이 이 문장으로 원고를 점검한다

## 적용 범위 (`apply_to`)

| 값 | 적용 대상 | 비고 |
|----|----------|------|
| `narration` | 서술 (웹소설) · 대지문 톤 (시나리오) | 가장 흔한 선택 |
| `inner` | 시점 인물의 내면 서술 (웹소설) | 속마음 드립의 말맛에 효과적 |
| `dialogue` | 대사 | 인물 말투(캐릭터 표)가 우선한다. 특정 인물에게만 줄 때는 인물명을 적는다 |
| `action` | 시나리오 지문 | 지문은 "보이는 것만" 원칙이 남으므로 어휘·리듬만 옮긴다 |

## 강도 (`intensity`)

| 값 | 옮기는 층위 |
|----|------------|
| `light` | 어휘 선택, 문장 끝 리듬 |
| `medium` | + 서술자의 거리·논평, 비유 방식 (기본값) |
| `strong` | + 문장 구조(길이 분포, 접속 방식). 웹소설에서는 1~10화 반응을 보고 결정하기를 권한다. 시나리오에서는 쓰지 않는다 |

## 출력 형식

```markdown
# 문체 프로필 — {작가} 《{작품}》 (+ 원전이 둘 이상이면 모두)

## 원전
- 작가 · 작품 · 발표 연도 · 저작권 상태(공유/보호) · 원문 대조 여부(파일명 | 원문 대조 없음)
- 적용 범위: narration / inner / dialogue(인물) / action · 강도: light | medium | strong

## 원전 진단
(이 문체가 어떻게 작동하는지 5~8줄. 공유저작물이면 인용은 원칙 2의 한도 안에서)

## 가져올 특징
| 층위 | 원전의 특징 | 이 작품의 적용 규칙 (측정 가능하게) |
|------|------------|------------------------------------|
| 문장 길이·호흡 | | |
| 어미·시제 | | |
| 서술자의 거리·논평 | | |
| 어휘층 (한자어·토박이말·입말) | | |
| 비유 | | |
| 해학·풍자·반어 | | |
| 대사 처리 | | |

## 가져오지 않을 것
- 시대 어휘·옛 표기 (현대 독자가 멈칫하는 것)
- 차별·비하 표현, 시대의 편견
- 원전의 고유 문장·유명 구절과 그 변형
- config `avoid` 항목

## 형식 규칙과의 충돌 조정
| 원전 특징 | 부딪치는 규칙 | 조정 |
|----------|--------------|------|

## AI 문투 점검 예외
(이 문체가 본래 쓰는 패턴 중 허용할 것과 한도. 예: "서술자 논평으로 끝나는 문장 — 장면당 1회". 한도 없는 예외는 두지 않는다.
"디테일 없음(유형 4)"은 어떤 문체에서도 예외로 두지 않는다)

## 변환 예시 (3쌍)
| 기존 문장 (또는 상황) | 프로필 적용 |
|---------------------|------------|
(오른쪽은 새로 쓴 문장만. 원전 문장 금지)

## Critic 점검 지표
- (3~5개. 예: "서술자 논평 장면당 1회 ±1", "한 문단 안 쉼표 3개 이하 유지", "입말 어미 '~것다' 회차당 5회 이내")
```

저장: `projects/{name}/output/style_profile.md`

## 완료 후

프로필을 사용자에게 보여 주고 **승인을 받은 뒤** 집필로 넘어간다 (Orchestrator가 묻는다).
수정 요청이 오면 프로필만 고치고, 이미 쓴 회차가 있으면 재집필 여부를 따로 묻는다.
